# Дескриптор модуля v0.2 (формат Pi HAT EEPROM, расширенный)

По D10: свои/модули сообщества несут ID EEPROM; вместо своего формата принимаем открытый формат Raspberry Pi HAT EEPROM (спецификация Pi HAT+), для которого есть утилиты (`eepmake`/`eepdump` из утилит Raspberry Pi).

## Аппаратная часть

- I2C EEPROM класса AT24C32, адрес 0x50..0x57 по номеру слота.
- Вывод write-protect: после программирования закрыт (WP на GND разрешает запись; в финальных модулях WP через площадку на 3V3).
- Питание от 3V3_LOGIC (пин 16 слота).

## Содержимое EEPROM (набор атомов, 256 байт)

| Смещение | Размер | Поле | Содержимое |
|----------|--------|------|------------|
| 0 | 4 | заголовок atom1 | сигнатура 0x52 'R' 0x2D '-', версия 0x01, count 2, по спецификации Pi HAT |
| 4 | 1 | общая длина | |
| 5..24 | 20 | uuid | 128-битный уникальный ID модуля (первые 6 байт — префикс производителя) | |
| 24 | 2 | pid | ID продукта (назначает производитель) | |
| 26 | 2 | pver | версия продукта (BCD) | |
| 28 | 1 | vsn | версия PCB | |
| 29 | 1 | используемые сигналы | битовая карта: bit0 SPI, bit1 I2C, bit2 UART, bit3 EN/PG, bit4..7 резерв | |
| 30 | 2 | макс. ток 5 В | мА, напр. 500 | |
| 32 | 2 | бросок тока 5 В | мА | |
| 34 | 1 | класс модуля | 0x01 LoRa, 0x02 GPS, 0x03 статус, 0x04 сеть, 0x05 DMR, 0x10.. своё | |
| 35 | 1 | регионы RF | bit0 433, bit1 868, bit2 915 МГц (0 = нет RF) | |
| 36..55 | 20 | имя ASCII | напр. "OFN-LORA-01" | |
| 56 | 1 | длина custom-данных | | |
| 57.. | n | custom-данные | полезная нагрузка производителя (пины, калибровка) | |

Структура: один атом формата HAT с нашими расширенными полями в вендорской области (смещение ≥ 28 по спецификации HAT). Всего 256 байт.

## Поток чтения (на стороне узла)

1. Слот запитан, EEPROM доступен по адресу 0x50+слот.
2. Проверка сигнатуры + CRC; при ошибке → слот считается модулем ручной конфигурации (D10 путь 1).
3. Читаются класс и лимиты тока → демон питания применяет лимиты ДО включения слота.
4. Имя/uuid → телеметрия и реестр модулей.
5. Регионы RF → проверка политики Gate 4 перед разрешением передачи.

## Поток программирования (производство модуля)

1. Модуль собран, EEPROM пустая; WP разомкнут.
2. На носителе (или доке Waveshare): `eepmake ofn-lora-01.txt ofn-lora-01.eep`, затем запись по I2C на 0x50.
3. Проверка через `eepdump`; закрыть площадку WP.

## Заметки о совместимости

- У готовых mikroBUS Click нет EEPROM → класс выбирается вручную из библиотеки приложения (D10 путь 1). I2C-скан может подсказать тип по известным адресам (например, GPS u-blox на 0x42).
- Дескриптор никогда не содержит исполняемого кода — только метаданные. Модулям security lab позже добавится поле подписи в custom-области (зарезервировано).
