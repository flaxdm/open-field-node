# Выбор сетевого модуля v0.2 (Wi-Fi AP, по D12)

MVP сетевой модуль даёт: GbE (фиксированно, на carrier) + Wi-Fi AP для управления телефоном. Варианты Wi-Fi части:

| Вариант | Железо | Плюсы | Минусы |
|---------|--------|-------|--------|
| A. USB-WiFi на H2 | Донгл класса RTL8811AU или MT7921AU, антенна IPEX на панель | ноль своей прошивки; стандартный Linux `hostapd`; работает на dev-станции уже сейчас | занимает единственный слот H2; донгл торчит, если не вывести на панель |
| B. ESP32-модуль в слоте Class L | ESP32-WROOM + своя прошивка модуля | интеграция: управление питанием слота, EEPROM-дескриптор, без расхода USB-бюджета | пишем и поддерживаем прошивку Wi-Fi+моста; больше запуска |
| C. ESP32 + Ethernet co-processor | ESP32 по проводу к CM5 | освобождает H2 | дублирование сетевого стека, сложность |

Рекомендация: **A для MVP** — канал управления это критичный софт (протокол приложение ↔ узел), поэтому берём вариант без своей прошивки: донгл MT7921AU (драйвер в ядре, хороший AP) или RTL8811AU, антенна IPEX на панели, `hostapd` на CM5. Вариант B вернёмся в v0.3, когда экосистема модулей созреет — ESP32 Wi-Fi карта в любом случае хороший модуль для сообщества.

Заметка про dev-станцию: тот же донгл работает на доке Waveshare уже сейчас — разработка control API стартует до появления носителя.

## Базовая конфигурация hostapd (для документов)

- Режим: g/n, 2.4 ГГц, фиксированный канал 6 (или наименее загруженный), ширина 20 МГц.
- SSID: OFN-<короткий-id>; WPA2/WPA3 transition, пароль из потока сопряжения.
- Нет DHCP к аплинку; dnsmasq обслуживает только телефоны в 10.0.0.x; узел на 10.0.0.1.
- Мощность TX: ≤ 14 dBm на старте по политике RF plan.
