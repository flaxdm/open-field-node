# OFN Идентичность узла и RTC v0.2

Две мелкие особенности носителя, которых не хватало в документах: собственная «паспортная» EEPROM узла и батарейка часов реального времени.

## 1. Паспортная EEPROM узла

У модулей свои EEPROM (MODULE-DESCRIPTOR-v0.2). У самого узла должна быть фиксированная идентичность для pairing, развёртывания нескольких узлов и поддержки.

- Чип: класса AT24C32, тот же, что у модулей, **фиксированный I2C-адрес 0x57** (EEPROM слотов занимают 0x50–0x56; 0x57 закреплён за узлом и слоту не выдаётся).
- Формат (256 Б, по возможности повторяет формат дескриптора модуля):

| Смещение | Размер | Поле |
|---|---|---|
| 0 | 4 | сигнатура: 0x4F 0x46 0x4E 0x31 ("OFN1") |
| 4 | 16 | UUID узла (случайный, пишется один раз на заводе/первом старте) |
| 20 | 4 | ревизия железа (ревизия PCB, BCD) |
| 24 | 8 | дата производства (Unix time) |
| 32 | 2 | битмап конфигурации (какие слоты заполнены на заводе, есть ли H1/H2) |
| 34 | 20 | ASCII-имя узла, по умолчанию "ofn-node" |
| 54 | 2 | CRC16 байтов 0–53 |
| 56..255 | — | резерв (0xFF) |

- Суффикс SSID берётся из UUID: `OFN-<первые 4 hex UUID>`, напр. `OFN-9f3a`. До provisioning заводской дефолт — `OFN-0000`.
- UUID пишется один раз (первый старт чистой платы сам дописывает, если область вся 0xFF). Дальше софт считает область read-only; менять — только подписанной сервисной командой.
- `ofn-ctl-api` отдаёт идентичность read-only по control API; Android-приложение показывает её в «О узле».

## 2. Батарейка RTC

Проблема: у CM5 часы реального времени есть, но питания батарейки на нашем носителе нет; узел в поле без GPS стартует с 1970 года и врёт в метках логов до первой синхронизации времени. Логи без доверенного времени для аудита бесполезны.

Решение: **держатель CR2032 + последовательный диод (BAT54) + 1 кОм к контактам RTC CM5** на носителе.

- Дёшево (~0.5 USD), жизнь 5–10 лет (RTC потребляет ~2 мкА).
- Диод не даёт батарейке запитать шину; 1 кОм ограничивает ток заряда, если батарейку вставили наоборот (дёшевая страховка).
- Приоритет синхронизации времени в софте: GPS-фикс → NTP при наличии интернета → время от телефона по control API → RTC. После любого лучшего источника RTC выставляется.
- Распиновка RTC-пинов CM5 Lite — по даташиту Raspberry Pi CM5; проверить при вводе схемы носителя в KiCad (открытая проверка).

Отвергнутые варианты: суперконденсатор (недели автономии, дороже, больше), никакого RTC (отвергнуто — полевым логам нужно время). Победила CR2032.

## 3. Дополнения в схему носителя (применить на входе в KiCad)

1. U7 AT24C32, адресные ножки на 0x57, на той же I2C-шине, что INA219/MCP23017.
2. BT1 держатель CR2032 + D-batt BAT54 + R 1 кОм к RTC_VCC CM5.
3. Обе части — в районе SODIMM, keep-out соблюдать; доступ к батарейке без разборки — плюс для корпуса v0.3, не блокирует.
