# Сборка прототипа P0 v0.2

Цель: работающая платформа только на стандартных платах — без единой самодельной PCB. Проверяет весь дизайн (дерево питания, слоты, канал управления, LoRa) до всякого ввода в KiCad.

## Архитектура P0

```
PDC004 (USB-C PD 12 В) ──► SS54 ИЛИ ──► PTC 5A ──► P-MOSFET от переполюсовки ──► TVS ──► VIN_12V
                                                                                  │
        ┌─────────────────────────────────────────────────────────────────────────┤
        │                                                                             │
   XL4015 (5.05 В)                                                              модуль 65 Вт PD
        │  5V_MAIN                                                           (выход зарядки)
        ├── TPS2553 ── Слот1 (LoRa RFM95W 868)
        ├── TPS2553 ── Слот2 (GPS, опционально)
        └── USB-A через ключ SY6280

   CM5 в доке Waveshare с собственным БП 27 Вт (в P0 ядро питает дока).
   Wi-Fi донгл (MT7921AU) в USB доки → hostapd → канал управления телефоном.
   INA219 ×2 + MCP23017 на I2C-хидере доки (логика 3.3 В).
   LoRa-модуль на UART GPIO (TX/RX + 3.3 В от доки, 5 В от нашего дерева).
```

Замечание: в P0 CM5 питается от собственного БП доки — наше дерево питает только слоты, выходы и логику. Это совпадает с финальной платой, где 5V_CORE идёт по выделенному ограничителю.

## Порядок сборки

1. Только дерево питания: PDC004 → защита → XL4015. Проверить 5.05 В на 5V_MAIN под нагрузкой 1 А (нагрузка на USB-резистор или лампочка).
2. Добавить SY6280 + USB-A, проверить лимит тока мультиметром.
3. Добавить TPS2553 №1 с резистором ILIM; проверить просадку при 2 А.
4. Добавить MCP23017 + INA219 по I2C; `i2cdetect` должен показать 0x20/0x40/0x41.
5. Добавить PD-модуль 65 Вт, проверить 9 В на телефоне.
6. Добавить RFM95W на шины слота 1 + UART; стендовый LoRa-пинг (позже, с сервисами ofn).

На каждом этапе — мультиметр до подключения следующего. Первое включение каждой ступени через БП с ограничением тока, если есть; иначе PTC + TPS2553 уже ограничивают ущерб.

## Поднятие софта (на доке)

1. Raspberry Pi OS Lite 64-bit на microSD, SSH через Ethernet доки.
2. hostapd по базовой конфигурации NETWORK-MODULE → телефон видит OFN AP; разработка control API начинается здесь.
3. Скелетные сервисы: ofn-powerd читает INA219; ofn-slotd дёргает EN MCP23017 и читает /FAULT; оба пишут логи в /var/lib/ofn.
4. LoRa: тест UART с RFM95W (meshtasticd, когда будет готов).

## Чего P0 НЕ покрывает

- PCIe H1, трассировка USB3 H2, SDR — территория кастомной платы.
- Аккумуляторный путь.
- Все шесть слотов (собрано только 2 ограничителя — в этом и смысл).
- Полевая защищённость.
