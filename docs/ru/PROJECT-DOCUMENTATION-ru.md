# Open Field Node — полная документация проекта (v0.2, 2026-11-25)

Этот документ — конспект всего проекта простым языком. Детали лежат в специализированных документах (ссылки в разделах). Структура: идея → принципы → железо → софт → процессы → история решений → глоссарий.

## 1. Что это такое

Open Field Node — открытая модульная полевая платформа без экрана и клавиатуры. Управляется со смартфона на Android. Сменное вычислительное ядро (Raspberry Pi CM5), модульные слоты под задачи: LoRa/Meshtastic, GPS, радионаблюдение (SDR), сеть, в перспективе — DMR, LTE, Wi-Fi. Платформа умеет работать автономно, писать логи и синхронизироваться с телефоном позже. Есть функции полевой «выживалки»: зарядка телефона, питание от чего угодно (аккумулятор, КЛЯ, солнечная панель), учёт потребления каждого модуля.

Ключевой сценарий: устройство без дисплея, управляемое телефоном, собранное из дешёвых распространённых компонентов, с открытой архитектурой — сообщество может делать свои модули.

## 2. Принципы проекта

1. **Не покупать лишнее.** Каждая покупка проходит через гейты (раздел 10). Spec v0.2 — не список покупок, а план, придуманный до них.
2. **Общепринятые решения.** Разъёмы, форматы и протоколы — из открытых стандартов (IDC 2.54 мм, формат Pi HAT EEPROM, mikroBUS-совместимый набор сигналов, USB-C PD), ничего экзотического.
3. **Безопасность.** Тестирование только собственных сетей и устройств, либо изолированного лабораторного стенда. Никакой работы против чужих систем.
4. **Сначала план.** Любое решение — сначала 2–3 варианта и обсуждение, исполнение — только по команде.
5. **Открытость.** Документация, схемы и код — открытые, формат модулей описан так, чтобы сообщество могло делать совместимые модули.

## 3. Архитектура (общая картина)

Устройство = вычислительное ядро + носитель (carrier) + силовая плата (backplane) + модули в слотах.

```
        ┌───────────────── Open Field Node ─────────────────┐
        │                                                    │
        │   ┌────────┐        ┌──────────────────────────┐   │
        │   │  CM5   │◄──────►│  carrier (носитель)       │   │
        │   │ ядро   │ SODIMM │  GbE, USB3, PCIe, I2C...  │   │
        │   └───┬────┘        └───────┬──────────────────┘   │
        │       │ 5V_CORE             │ шины                  │
        │   ┌───┴────┐        ┌───────┴──────────────────┐   │
        │   │ backplane (силовая)                       │   │
        │   │ 12В вход → 5В/6А → слоты ×6 по 2А        │   │
        │   │ мониторинг, зарядки                       │   │
        │   └───┬────┘        │                          │   │
        │   ┌───┴───┬───┬───┬─┴──┬───┬───┐               │   │
        │  LoRa  GPS  …  …   …   …  (модули в слотах)      │   │
        └────────────────────────────────────────────────────┘
                    ▲ Wi-Fi точка доступа
              телефон (Android-приложение)
```

- **Ядро (CM5 8GB Lite, без радиомодулей)** — самостоятельный Linux-компьютер. Работает и без нашей платы (в доке). В поле живёт внутри узла. Решение D1.
- **Носитель** — плата под ядро: сетевой порт, высокоскоростные слоты, разводка шин к слотам. Проект: `CARRIER-SCHEMATIC-v0.2`.
- **Backplane** — силовая часть: входы, преобразователи, шесть ограниченных каналов 5 В, мониторинг, выходы зарядки. Проект: `BACKPLANE-SCHEMATIC-v0.2`.
- **Модули** — карточки 22×60 мм (механика: `MECHANICAL-v0.2`). Два класса слотов: L (низкоскоростные, IDC 2×8) и H (высокоскоростные: один PCIe x1, один USB3). Решение D7.

Подробно: `SPEC-v0.2`, `ARCHITECTURE.md`, `MODULE-STANDARD.md`.

## 4. Питание

### Входы (D8)

Два входа объединяются по ИЛИ, приоритет у полевого:

1. **XT30** — полевой разъём, 8–18 В (аккумулятор, КЛЯ, солнечная панель). Ток до 5 А.
2. **USB-C** — «городской» вход через PD-триггер (CH224K/IP2721), запрашивает 12 В у любого PD-зарядника.

Защита: диоды Шоттки SS54 (объединение), P-MOSFET от переполюсовки, TVS от бросков, PTC-предохранители.

### Дерево питания

```
12 В (XT30 приоритет / USB-C PD) → защита → buck 5 В/6 А (backbone)
                                        ├── 6 слотов × TPS2553 (2 А каждый, EN + флаг ошибки)
                                        ├── 3.3 В/2 А (логика, EEPROM)
                                        └── USB-A 5 В/2.4 А (зарядка)
12 В ветвь → PD-источник 9 В/2 А или 12 В/1.5 А (быстрая зарядка USB-C)
12 В сквозные → резерв под будущий RF-усилитель
```

### Политика мощности (Gate 1, пройден)

- Потолок по слотам: суммарно 3 А; отсечка при перегрузе в порядке: USB-A → слоты 6..1 → ядро никогда.
- Питание от USB-C входа — «low power mode»: зарядки ограничены, приложение уведомлено.
- Ядро CM5 — на выделенном канале 3 А, ни с кем не делится.

Документы: `POWER-ARCHITECTURE-v0.2`, `POWER-BUDGET-v0.2`, `READY-MODULES-v0.2` (готовые модули для стенда).

## 5. Модули и слоты

### Слот класса L (низкоскоростной) — IDC 2×8, 16 пин

Питание 5 В на трёх пинах (2 А), земля, I2C, UART, SPI, сигналы включения/контроля, 3.3 В логика. Набор сигналов совместим с mikroBUS (стандарт модульной экосистемы) — наши модули близки к готовым Click-модулям, полная разъёмная совместимость оставлена открытым вопросом до разводки.

### Слоты класса H

- **H1**: PCIe x1 edge-разъём — SDR, NVMe, второй Ethernet (резерв D3).
- **H2**: USB3 19-pin — USB-WiFi донгл (канал управления), USB-SDR, накопитель.
- Правило: не более двух высокопропускных USB-устройств, управляющие модули — никогда по USB.

### Идентификация модулей (D10)

- Готовые сторонние модули (без чипа-ID): тип задаётся вручную в приложении; I2C-скан даёт подсказку по известным адресам.
- Свои модули: EEPROM в формате Raspberry Pi HAT (открытый стандарт) с нашими полями — класс, лимит тока, регионы RF, имя, UUID. Устройство само узнаёт такой модуль, применяет лимиты до включения, запрещает передачу вне региона.

Документы: `MODULE-CONNECTOR-v0.2`, `MODULE-DESCRIPTOR-v0.2`, `MODULE-STANDARD.md`.

## 6. Программная часть

### Канал управления (D12)

Wi-Fi точка доступа на узле (USB-WiFi донгл MT7921AU/RTL8811AU на слоте H2). Телефон подключается к точке OFN, управляет узлом; мобильный интернет телефона не затрагивается. Запасной вариант — USB-C кабель. Выбор обоснован в `NETWORK-MODULE-v0.2`: ноль своей прошивки, стандартный Linux hostapd, тот же донгл работает на стенде разработки.

### Сервисы узла (Linux, systemd)

| Сервис | Задача |
|--------|--------|
| ofn-powerd | Мониторинг INA219, политика отсечки, low-power режим |
| ofn-slotd | Опрос слотов, EEPROM-дескрипторы, ручная конфигурация |
| ofn-modmgr | Реестр модулей, привязка драйверов |
| ofn-mission | Миссии: расписания, LoRa-сессии, сбор данных |
| ofn-logd | Локальные логи и хранилище |
| ofn-syncd | Синхронизация с телефоном при подключении (store-and-forward) |
| ofn-ctl-api | Единая точка входа для приложения: WebSocket + JSON, TLS, сопряжение по коду |

### Android-приложение

Kotlin, offline-first. Экраны: дашборд питания/телеметрии, модули, миссии, логи, настройки. Приложение — дисплей устройства; всё планирование миссий на телефоне.

### Survival mode

Без телефона узел сам выполняет запланированные миссии и пишет логи. С батареей (отдельный гейт, post-MVP) — автономный переход на батарейный профиль.

Документ: `SOFTWARE-ARCHITECTURE-v0.2`. API-протокол описан там же (WebSocket, JSON, события).

## 7. Радиочасть (RF)

Регион: **868 МГц** (D13), профиль LoRaWAN RU864. 433 МГц — запасной вариант.

- LoRa-модуль: SX1276-класс (RFM95W 868), до 25 мВт, антенна на лицевую панель.
- Wi-Fi управления: 2.4 ГГц, минимальная мощность, фиксированный канал, без выхода в интернет.
- SDR в MVP — только приём. DMR — post-MVP, с отдельной легальной проверкой.
- Разнос антенн: Wi-Fi от LoRa ≥ 5 см, GPS — в самый дальний от Wi-Fi слот, SAW-фильтр в посадочном месте GPS-модуля.
- Модули с передачей несут битовую карту регионов; прошивка запрещает TX вне региона.

Документ: `RF-PLAN-v0.2`. Перед покупкой радиожелеза — чеклист Gate 4 (в том числе сверка актуальных правил RU/EU по мощности и duty cycle).

## 8. Механика

- Плата 160×100 мм, 4 слоя, 6 слотов в ряд с шагом 25 мм; карточки модулей 22×60 мм.
- Лицевая панель: XT30 → USB-C вход → USB-C зарядка → USB-A → 6 антенных разъёмов → RJ45.
- Корпус-ориентир 170×110×35 мм: алюминиевый профиль (экранирование) или печатный PETG на прототип.
- Охлаждение CM5: пассив с рёбрами, запас — вентилятор 30 мм.

Документ: `MECHANICAL-v0.2`.

## 9. Путь прототипа P0 (текущий этап)

Принципиальное решение: **сначала вся платформа собирается на стандартных платах**, самодельной PCB нет.

- CM5 в доке Waveshare BASE-A (питается от своего БП).
- Силовая часть на перфорированной плате из готовых модулей: PDC004 (PD-триггер 12 В), SS54, PTC, MOSFET, TVS, XL4015 (5 В/6 А), TPS2553 ×2 (два слота), SY6280 (USB-A), PD-модуль 65 Вт (быстрая зарядка).
- Мониторинг: INA219 ×2 + MCP23017 по I2C.
- Wi-Fi донгл в доке → hostapd → управление с телефона.
- LoRa RFM95W 868 на UART GPIO.
- Порядок сборки по ступеням с проверками — в документе.

Добавка к закупке ~3–3.5 тыс. ₽. После P0 — ввод схем в KiCad и заказ полевой платы.

Документ: `P0-PROTOTYPE-v0.2`. Покупки: `DEV-STATION-BUYLIST` (итого первая закупка ~28–30 тыс. ₽).

## 12. Глоссарий (простыми словами)

- **CM5** — вычислительный модуль Raspberry Pi: полноценный компьютер размером с планшетную флешку, втыкается в носитель.
- **Backplane** — «материнская» силовая плата: раздаёт питание слотам и следит за потреблением.
- **Carrier (носитель)** — плата, в которую втыкается CM5 и которая соединяет ядро с backplane и слотами.
- **Слот/бей (bay)** — посадочное место модуля с разъёмом и питанием.
- **IDC 2×8** — стандартный штыревой разъём 16 пин (2 ряда по 8), шаг 2.54 мм, с ключом против перепутывания.
- **PD (Power Delivery)** — протокол USB-C, по которому устройство договаривается с зарядником о напряжении (у нас — 12 В на входе, 9/12 В на выходе зарядки).
- **Buck** — понижающий преобразователь напряжения (12 В → 5 В).
- **TPS2553** — микросхема-кран: пускает ток до заданного предела (2 А), при превышении ограничивает и сигнализирует.
- **INA219** — измеритель тока/напряжения на I2C-шине.
- **MCP23017** — расширитель GPIO: добавляет 16 управляемых линий для включения слотов и приёма сигналов ошибок.
- **EEPROM** — маленькая память на модуле, где лежит «бирка» (кто я, сколько тока нужно).
- **Pi HAT** — стандарт расширений Raspberry Pi; его формат EEPROM мы используем для «бирок».
- **mikroBUS** — открытый стандарт модульных плат (Click): 16 сигналов, совместимых с нашим слотом L.
- **hostapd** — программа, превращающая Wi-Fi адаптер в точку доступа.
- **I2C/SPI/UART** — три стандартных «языка» связи микросхем: I2C — адресная двухпроводная, SPI — быстрая, UART — последовательный порт.
- **LoRa** — дальнобойная радиосвязь малой мощности; Meshtastic — сеть поверх LoRa.
- **SDR** — программно-определяемая радиосвязь (приём/анализ радиоспектра).
- **XT30** — стандартный силовой разъём (как в дронах), до 15 А.
- **Гейт** — контрольная точка: пока не пройдена, покупка по этому пункту запрещена.
- **BOM** — список всех деталей сборки.

## 13. Дорожная карта

1. **Сейчас**: закупка dev-станции + P0 (единственное разрешённое действие с деньгами).
2. **P0 на столе**: сборка по ступеням, hostapd, скелеты сервисов, LoRa-пинг.
3. **Софт**: приложение Android + control API на живом стенде.
4. **KiCad**: схемы carrier и силовой части → ревью → заказ платы (Gate 3).
5. **Полевая плата**: CM5 переезжает с доки, первая сборка в корпусе.
6. **Post-MVP**: батарея (LiFePO4, отдельный гейт), DMR/LTE/SDR-модули, ESP32 Wi-Fi карта как модуль сообщества.
