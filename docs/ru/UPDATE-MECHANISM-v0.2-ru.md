# OFN Механизм обновления ПО v0.2

Как софт узла обновляется в поле. Зафиксировано до P1, чтобы архитектура сразу была обновляемой — переписывать потом дороже.

## 1. Принципы

1. **Один узел — один источник истины.** Обновление всегда приходит «сверху вниз»: сначала телефон/оператор, потом узел. Узел сам ничего не тянет из интернета без команды.
2. **Атомарность и откат.** Обновление не должно оставлять узел «кирпичом»: всегда есть рабочий предыдущий слот.
3. **Подпись.** Принимаются только пакеты, подписанные ключом проекта (ed25519). Это open-source проект, но обновления на живой узел — не с анонимного форума.
4. **Канал — любой.** Wi-Fi AP + телефон, USB-C tethering, microSD вручную. Узел в поле не обязан иметь интернет.

## 2. Схема: двухслотовое обновление (A/B)

Карта памяти разбита на два корневых раздела (rootfs A и rootfs B) плюс общий boot-раздел. Активный слот загружается, неактивный — стейджинг.

1. Пакет обновления (`ofn-update-<ver>.tar`, подпись отдельным файлом) попадает на узел через приложение или USB.
2. `ofn-syncd` проверяет подпись и формат, распаковывает в **неактивный** слот.
3. Переключение boot-флага → перезагрузка → новый слот.
4. Watchdog первых 5 минут: если сервисы не поднялись / core недоступен, автоматический откат на предыдущий слот, флаг `update.rollback` в логе.
5. Если всё ок — предыдущий слот остаётся как резерв до следующего обновления.

Плюс: microSD на 64 ГБ с запасом; каждый слот ~8–10 ГБ, остальное под логи и миссии.

## 3. Уровни обновления

| Уровень | Что | Как |
|---|---|---|
| Сервисы (ofn-*) | чаще всего | пакет внутри rootfs, приезжает с обновлением rootfs |
| Конфиги/миссии | постоянно | через control API, без перезагрузки |
| Ядро/boot | редко | вместе с rootfs, тем же A/B механизмом |
| Дескрипторы модулей | редко | пакет данных через control API |

Bootloader (EEPROM CM5) — руками, сервисным режимом, в документации, но не «по воздуху».

## 4. Что нужно на P1 (для KiCad и сборки образа)

- Разметка образа SD: `bootfs` (FAT, 512 МБ) + `rootfs_a` + `rootfs_b` + `data` (логи/миссии).
- Два boot-флага в `data`: `active_slot`, `boot_attempts`.
- `ofn-syncd` — уже есть в архитектуре, добавляются проверка подписи и переключение слота.
- Публичный ключ проекта зашит в rootfs (read-only часть), приватный — у релизера (тебя), отдельный документ «релизный процесс» — к релизу, не сейчас.

## 5. Отклонённые варианты

- **OTA с GitHub напрямую** — узел в поле часто без интернета; плюс доверие к каналу сложнее. Отклонено для MVP, остаётся опцией позже (через тот же подписанный пакет, просто канал доставки другой).
- **Обновление «поверх» без A/B** — любой сбой посередине = кирпич, отклонено сразу.
- **Обновление только через перезапись SD на компьютере** — годится для P0 и ранней разработки, но не для поля; оставлено как аварийный путь (recovery).
